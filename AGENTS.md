# Project workflow

Keep changes small and understandable. Complete tests and relevant lint/type checks before committing.
Review staged files and the complete outgoing history before each push. Never publish credentials, secrets, private briefs, learning notes, environments or generated caches. If sensitive material is uncertain, stop and report before publication; do not rewrite history automatically.
Use factual commit messages and README claims that match implemented behavior. Push meaningful completed and tested work only when publication is authorized. Do not make empty activity commits.
Private learning notes belong in the ignored local-notes folder. Daily progress does not authorize automatic coding, extra features or deployments.
